# 数字图像处理 Project 04-03、04-04、04-05 三人详细分工方案

> 说明：本文档使用“成员 A / 成员 B / 成员 C”作为占位，不包含真实姓名和学号。正式提交前，可根据课程要求替换为实际小组成员信息。

## 一、三人分工总表

| 成员 | 主要负责内容 | 对应 Project | 核心职责 | 主要交付物 | 依赖关系 |
|---|---|---|---|---|---|
| 成员 A | 基础框架、图像读取与预处理、Project 04-03 实现 | Project 04-03 | 搭建统一代码结构；完成输入图像读取、灰度化、归一化、显示与保存接口；实现 04-03 的算法、结果图与初步分析 | `project_04_03` 相关代码、测试图像结果、公共工具函数、04-03 实验记录 | 向成员 B 提供统一图像处理接口、样例输出和参数说明 |
| 成员 B | Project 04-04 算法实现与对比实验 | Project 04-04 | 基于成员 A 的公共接口完成 04-04；设计不同参数或不同图像条件下的对比实验；整理实验现象 | `project_04_04` 相关代码、对比结果图、参数记录、04-04 分析文字 | 依赖成员 A 提供的输入输出规范、预处理流程和公共函数 |
| 成员 C | Project 04-05 实现、整体整合与报告排版 | Project 04-05 | 完成 04-05；统一三项 Project 的结果命名、目录结构和报告格式；汇总成员 A/B 的结果与说明 | `project_04_05` 相关代码、整合后的结果目录、完整实验报告、贡献表 | 与成员 A/B 并行推进；后期依赖 A/B 的最终结果进行报告整合 |

## 二、成员 A 详细任务清单

### 1. 公共基础工作

- 建立统一工程目录结构，建议包括：
  - `src/`：存放核心代码；
  - `data/`：存放输入图像；
  - `results/`：存放输出图像与实验结果；
  - `docs/`：存放报告草稿和说明材料。
- 编写通用图像处理函数：
  - 图像读取；
  - RGB 图像转灰度图；
  - 像素值归一化；
  - 图像显示；
  - 图像保存；
  - 基本参数检查。
- 统一输出文件命名规则，例如：
  - `04_03_original.png`
  - `04_03_result_param1.png`
  - `04_04_result_compare_a.png`
  - `04_05_result_final.png`

### 2. Project 04-03 实现

- 阅读 Project 04-03 的任务要求，明确输入、处理步骤、输出形式和评价方式。
- 完成 04-03 对应算法的代码实现。
- 至少选择 1-2 张测试图像进行运行验证。
- 保存原图、关键中间结果图和最终结果图。
- 记录主要参数设置，并说明参数变化对结果的影响。
- 撰写 04-03 部分的实验过程和结果分析。

### 3. 成员 A 交付文件

| 文件或目录 | 内容说明 |
|---|---|
| `src/common_io.*` 或同类文件 | 图像读取、保存、显示等公共函数 |
| `src/project_04_03.*` | Project 04-03 的核心实现 |
| `results/04_03_*` | Project 04-03 输出结果图 |
| `docs/04_03_notes.md` | 04-03 实验步骤、参数和结果分析 |
| `docs/interface_notes.md` | 提供给成员 B 的公共接口说明 |

## 三、成员 B 详细任务清单

### 1. 接收并使用成员 A 的公共接口

- 检查成员 A 提供的图像读取、预处理和保存函数是否能够直接用于 04-04。
- 确认输入图像格式、灰度范围、保存路径和文件命名规则。
- 若需要新增辅助函数，应尽量保持与成员 A 的代码风格一致。

### 2. Project 04-04 实现

- 阅读 Project 04-04 的任务要求，明确算法目标和实验输出。
- 基于成员 A 的公共框架实现 04-04。
- 设计对比实验，例如：
  - 不同输入图像；
  - 不同参数设置；
  - 不同处理阶段的结果对比；
  - 与 04-03 结果的差异分析。
- 保存对比结果图，并保证图名清晰可追溯。
- 记录运行中遇到的问题、参数选择依据和实验观察。

### 3. 成员 B 交付文件

| 文件或目录 | 内容说明 |
|---|---|
| `src/project_04_04.*` | Project 04-04 的核心实现 |
| `results/04_04_*` | Project 04-04 输出结果图与对比图 |
| `docs/04_04_notes.md` | 04-04 实验步骤、参数记录和分析文字 |
| `docs/04_04_compare_table.md` | 不同参数或不同图像条件下的对比表 |

## 四、成员 C 详细任务清单

### 1. Project 04-05 实现

- 阅读 Project 04-05 的任务要求，明确算法流程、实验输入和预期输出。
- 在统一工程结构下完成 04-05 的代码实现。
- 选择合适测试图像，保存原图、中间结果和最终结果。
- 记录关键参数，并分析其对实验结果的影响。
- 与 04-03、04-04 的结果进行必要的横向比较。

### 2. 整体整合与报告编写

- 收集成员 A、成员 B 的最终代码、结果图和实验说明。
- 检查三项 Project 的文件命名、图片尺寸、图注风格和分析格式是否统一。
- 整理完整实验报告，建议包含：
  - 实验目的；
  - 实验原理；
  - 实验环境；
  - Project 04-03 实现与结果；
  - Project 04-04 实现与结果；
  - Project 04-05 实现与结果；
  - 结果分析与讨论；
  - 小组分工与贡献表；
  - 总结。
- 对全文进行格式检查，确保图表编号、引用和排版一致。

### 3. 成员 C 交付文件

| 文件或目录 | 内容说明 |
|---|---|
| `src/project_04_05.*` | Project 04-05 的核心实现 |
| `results/04_05_*` | Project 04-05 输出结果图 |
| `docs/04_05_notes.md` | 04-05 实验步骤、参数记录和分析文字 |
| `docs/final_report.md` 或实验报告文档 | 整合后的完整实验报告 |

## 五、A → B 的技术依赖与交接事项

成员 B 的 04-04 实现依赖成员 A 先完成公共基础框架，因此 A 到 B 的交接需要明确、可运行、可复现。

### 1. 成员 A 需要交接给成员 B 的内容

| 交接内容 | 具体要求 |
|---|---|
| 公共图像读取函数 | 说明输入路径、返回图像格式、灰度范围和异常处理方式 |
| 图像预处理流程 | 明确是否进行灰度化、归一化、滤波、尺寸调整等步骤 |
| 输出保存函数 | 说明输出目录、文件命名规则、图像格式和覆盖策略 |
| 示例运行方式 | 提供一组可直接运行的示例输入和输出结果 |
| 参数说明 | 说明默认参数含义、推荐取值范围和修改位置 |
| 已知问题 | 标明当前代码中可能存在的限制或待完善部分 |

### 2. 成员 B 接收后的确认事项

- 能够在本地成功运行成员 A 的示例代码。
- 能够使用成员 A 的公共函数读取 Project 04-04 所需图像。
- 确认 04-04 的输出能够保存到统一 `results/` 目录。
- 若发现接口不满足 04-04 需求，应及时反馈给成员 A，由 A 调整公共函数或双方约定新增函数。

### 3. A → B 交接清单

| 检查项 | 状态 |
|---|---|
| 公共函数文件已提交 | 待确认 |
| 示例图像可正常读取 | 待确认 |
| 示例结果可正常保存 | 待确认 |
| 参数说明已写入文档 | 待确认 |
| 成员 B 已完成本地运行验证 | 待确认 |

## 十、协作注意事项

- 三位成员应使用统一的文件命名方式，避免结果图混乱或覆盖。
- 每个 Project 的参数设置必须记录清楚，确保实验结果可复现。
- 成员 A 的公共接口若发生修改，应及时通知成员 B 和成员 C。
- 成员 C 在整合报告时不应随意改动 A/B 的实验结论，如需调整应先与对应成员确认。
- 最终提交前，三位成员应共同检查代码能否运行、结果图是否完整、报告内容是否与实验结果一致。
